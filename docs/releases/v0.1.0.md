The first public release of **flipbook**: a local-first, content-focused PDF magazine viewer.

### Start

- Single-viewport welcome page with a prominent Upload PDF button and drag-and-drop.
- Alternative public PDF URL entry; Internet Archive download links load through its first-party CORS endpoint.
- Vriksh Apps footer with referral UTM tags.
- Sage, White and true-black Dark themes, selected from the bottom controls and remembered between visits.

### Reading experience

- Interactive page folds with shadows, synthesized paper sound and mute.
- Paper stacks that reflect progress; hover across their thickness to preview a number and click to jump.
- Selectable PDF text directly in the reader and in zoom.
- Paired spread thumbnails with numeric labels and an outline only on the active spread.
- Full-document text search with excerpts and navigation.
- Notes, bookmarks and reading position saved per document in browser storage, validated on load, with visible write-failure warnings and JSON backup export.
- Compact title/page controls at the top left, search at the far right, subtle bottom icons.
- Local PDF opening, drag-and-drop, zoom, spread links, download and fullscreen.
- Printing via the browser's PDF viewer; external PDF links in zoom.
- Keyboard navigation, stack target controls and reduced-motion support.

### Open source package

- MIT license, original vector logo and favicon, self-hosted fonts and PDF.js support assets.
- Original 24-page sample; private demo documents are excluded from Git and release builds.
- CI on Node 22 and 24, navigation tests and repeatable release packaging.
- Contribution, security, privacy, accessibility, deployment and release documentation.

### Download

Unzip `flipbook-v0.1.0-web.zip` and serve it over HTTP with a static web server. Do not open `index.html` as a `file://` URL. Verify the archive with `SHA256SUMS.txt`. GitHub also provides source archives.

### Maturity

This is an early **0.x prerelease**. Core desktop interactions have been exercised in Edge. Physical touch, mobile browsers, accessibility with assistive technology, password-protected PDFs and unusually large/mixed-size PDFs need broader testing. There is no OCR, cloud sync, publishing backend, offline service worker or guarantee of pixel-identical behavior to another viewer. See the README for the feature and verification boundaries.
